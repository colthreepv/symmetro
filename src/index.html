How Encrypt / Decrypt works +

Protect a private note before saving it, or share encrypted text with someone who knows the password. Keep that password separately; Symmetro cannot recover it.

Clear text and encrypted text

Clear text is the readable, unencrypted message. Encryption conceals it; decryption recovers it with the password. In Decrypt, Symmetro checks the password as you type. The recovered message stays hidden until you choose Show Clear Text, so you can decide when to display potentially sensitive content.

AES: the same key both ways

AES, the Advanced Encryption Standard, locks and unlocks text with the same secret key. This is called symmetric encryption. Symmetro calculates a 256-bit key from your password, so the same password can unlock the result later. Anyone who has both the password and encrypted text can read the message.

SHA-256: a fingerprint, not encryption

A hash turns input into a fixed-size fingerprint. SHA-256 produces a 256-bit fingerprint and is designed to work one way: there is no decoding step to recover the input. Different inputs can share a fingerprint, so it is not a unique identifier. Someone can still guess a weak input and check whether its fingerprint matches.

PBKDF2: turning a password into a key

PBKDF2 is a password-to-key calculation. It uses HMAC, a hash calculation with a key, built here from SHA-256. Repeating the work 100,000 times makes each password guess more expensive; it does not encrypt the message 100,000 times. This count is fixed to preserve compatibility with existing messages. An easily guessed password remains vulnerable.

GCM: checking for changes

GCM is the way Symmetro applies AES while also creating a tamper-check value, called a tag. Decryption checks that tag before accepting the message. A wrong password or altered encrypted result makes the check fail. It does not identify the sender: anyone with the password can create a valid message.

Salt: a different key for each message

A salt is an extra value mixed into the password-to-key calculation. Symmetro generates a fresh random 16-byte salt for every encryption, so reusing a password does not reuse the same calculation. This limits reuse of prepared password guesses across messages. The salt is public and travels inside the encrypted result.

IV: a fresh starting value

An initialization vector, or IV, gives the encryption operation its starting value. Symmetro generates a fresh random 12-byte IV for each message; the same key must not reuse an IV. It is public and included in the result. Together with the random salt, it makes repeated encryptions of the same message look different.

Base64: packaging you can copy

Base64 represents bytes as copyable text using letters, digits, symbols, and optional padding. It adds no secrecy. Symmetro packages the salt, IV, encrypted message, and tag this way automatically; these are not settings you need to choose. Save the complete result and keep the password separately. Anyone with the result can try password guesses offline.

How Derive works +

Recreate passwords from one strong base passphrase. Use a different password number for each account. Changing the length alone does not create an independent password.

Recreate a password when you need it

Keep each account's number and selected length. Re-enter the exact secret, including spaces and case, to recreate its password. Use a new number when changing a password, and update it at the account itself. A typo produces a different password without a warning. Symmetro cannot recover a forgotten secret.

Argon2id: making guesses cost more

Argon2id turns your base secret into an internal secret value, called a root key, from which numbered passwords are calculated. It deliberately requires memory as well as computation, making large numbers of guesses more expensive. This is what memory-hard means. Use a long, unpredictable secret: extra work cannot make an easily guessed secret safe.

Why 64 MiB, three passes, four lanes?

64 MiB (mebibytes, about 67 megabytes) is the working-memory budget, with three passes over it. Four lanes divide the work within that budget. These settings balance the cost of guessing against memory use and waiting time on your device. They match a profile recommended in the Argon2 specification. Browser overhead adds to memory use.

SHA-256: a one-way fingerprint

A hash produces a fixed-size fingerprint of its input. SHA-256 produces 256 bits. It is not encryption and cannot be decoded to recover the input; different inputs can also have the same fingerprint. Guessing remains possible: someone can calculate fingerprints of likely inputs and compare them. HMAC adds a secret key to a hash calculation.

HKDF: choosing the numbered output

HKDF turns the internal root key from Argon2id into a password for each number. It uses HMAC, a hash calculation with a key built from SHA-256, and mixes in the number and a fixed label for Symmetro. Changing the number changes the output. Argon2id makes guessing expensive; HKDF produces the separate numbered passwords.

Fixed salts: the recovery tradeoff

A salt is an extra input to a calculation. Derive uses fixed public salts so you need no saved random value to recreate passwords. Identical inputs give identical passwords across users, allowing guessing work to be reused. A disclosed password permits offline secret guesses. It does not directly reveal other passwords, but finding the secret exposes every number.

Full result and shorter lengths

Recipe v1 produces 32 bytes, written as 43 base64url characters: letters, digits, hyphen, and underscore, without padding. Max keeps the full result; 16 and 24 keep its first characters. Length changes the final credential without changing the recipe. 16 is this tool's minimum preset. Sites may require other lengths or characters.

Recipe 1: keeping passwords reproducible

A recipe identifies the exact calculation and character format. Recipe 1 is fixed so the same inputs keep producing the same password. Only version 1 is currently available. Its number is a compatibility identifier, separate from the app release and encryption format, not an adjustable strength setting. Keep it with your account-to-number notes.
