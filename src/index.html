How Encrypt / Decrypt works +

Protect a text note for storage, or share encrypted text with someone who knows the password. Keep the password separately; Symmetro cannot recover it.

One password, both ways

AES (Advanced Encryption Standard) is a symmetric cipher: the same key locks and unlocks the text. Symmetro derives a 256-bit key from your password. Its GCM mode also checks for tampering; a wrong password or altered message fails to decrypt. It does not verify who sent the message.

Why PBKDF2?

A password is not an encryption key. PBKDF2 (Password-Based Key Derivation Function 2) converts it into one using SHA-256. The 100,000 iterations repeat this work to make each password guess more expensive. This is a fixed compatibility setting, not 100,000 encryptions, and it cannot make a weak password strong.

Random salt

A fresh 16-byte salt changes the password-to-key calculation for each message, even if you reuse a password. It limits reuse of precomputed guesses across messages. The salt is public and included in the result.

IV: a fresh starting value

The initialization vector (IV), also called a nonce here, is a fresh random 12-byte value for AES-GCM. A key must never reuse the same IV. Symmetro generates it for you and includes it in the result; it does not need to be secret.

Decisions made for you

The cipher, key derivation, iteration count, salt, IV, and 128-bit tamper-check tag are fixed or generated automatically. The result packages salt, IV, and encrypted text with its tag as copyable base64 text. Base64 is an encoding, not the encryption.

What you keep

You need the complete encrypted text and the exact password to decrypt later. Processing stays in your browser and the downloaded HTML works offline. Inputs are not saved. Anyone with the encrypted text can try password guesses offline.

How Derive works +

Recreate numbered passwords without storing a password list. The same base secret, number, and recipe always give the same password. This generates a password; it does not encrypt a message.

When it is useful

Use different numbers for different accounts, or a new number when changing a password. Keep your own number-to-account mapping: Symmetro has no service names or saved profiles. You must also change the password at the account itself; generating a new one does not update it there.

Argon2id: work + memory

Argon2id turns your secret into a root key, with a deliberate cost in computation and memory to make guessing more expensive. The id variant combines approaches aimed at resisting memory shortcuts and side-channel attacks.

64 MiB, 3 passes, 4 lanes

64 MiB is the algorithm's memory budget; three iterations mean three passes over that memory. Four lanes divide the work into cooperating chains, not four times the memory or a promise of four browser threads. These memory and work settings match RFC 9106's second recommended Argon2id profile: a smaller memory budget than its first recommendation, with more passes. Browser overhead adds to memory use.

HKDF: one output per number

HKDF (HMAC-based Key Derivation Function), using SHA-256, takes the root key and combines it with the password number and a fixed purpose label. This separates the numbered outputs. It is not the slow password-hardening step and does not add unpredictability to a weak secret.

The recovery tradeoff

Recipe v1 uses fixed public salts so no personal salt needs to be saved. Identical inputs give identical passwords for everyone. A known output allows offline guesses of the secret; a successful guess exposes all its numbers. Use a long, unpredictable base secret. A typo produces a different password without a warning.

Why a recipe version?

A recipe identifies the exact calculation, including parameters and output format. Only v1 exists; more versions are not currently promised. A future change would need a new recipe while keeping v1 available to recreate old passwords. It is separate from the app version and encryption format. Outputs are 43 base64url characters; some sites may reject that format.
